# 륜 지출 기입장 점검 (2026-11-06)

| 경로 | 기록 방식 | 점검/수정 |
|---|---|---|
| 상점·잡화점·여와·씨앗·비료 | 실제 로컬 륜 변동 측정 | 기존 함수 누락 검사 통과 |
| 강화·재련·제작·요리·외출·시험·거처 공사·단독 일세 | 행동 전후 륜과 수입 분리 | 중첩 일괄 행동은 최상위에서 한 번만 기록 |
| 떠돌이 상인 입찰 | 경매 지갑의 실제 차감 트랜잭션 | 서버에 ‘떠돌이 상인 입찰’ 기록 추가 |
| 더 높은 입찰에 따른 반환 | 이전 최고 입찰자 지갑에 실제 입금 | 서버에 ‘경매 입찰금 반환’ 기록 추가 |
| 낙찰품 수령 | 재차 륜을 차감하지 않음 | 0원 기록을 추가하지 않음 |
| 중개소 구매·판매대금 인출 | 실제 거래 확정 지점의 순변동 | 서버 기록 추가, 화면 잔액 조회를 지출로 중복 기록하지 않음 |
| 공동 일세 | 실제 납부 영수증 생성 직전 | 납부자에게 기록, 읽기·재요청은 재기록하지 않음 |
| 동아리 기부·금고 출납·시설 | 출납 영수증 생성 직전 | 실제 륜 차이만 기록; 물품만 이동하면 0건 |
| 파트너 활동으로 인한 잔액 조회 | 기록하지 않음 | 파트너/서버 기록을 그대로 조회 |

서버 이벤트는 요청 처리 트랜잭션 안에 기록됩니다. 영수증/재실행 방지는 기존 거래 함수가 담당하며, 동일 이벤트 ID는 목록 새로고침 시 중복 표시하지 않습니다. 기존 클라이언트의 늦은 저장이 서버 이벤트를 덮어쓰지 않도록 저장 보호 함수에서도 보존합니다. 구버전 거래 저장 거부 검사는 유지합니다.

## 적용

1. `supabase/ledger-money-events.sql` 전체 실행. 기존 함수 구조가 예상과 다르면 예외를 내고 전체 롤백합니다.
2. 클라이언트 배포. 서버 기록은 계정 인증 후 본인과 현재 페어의 내역만 조회합니다.
3. 단독/페어 입찰→추월 환불, 구매→판매대금 인출, 일세, 동아리 기부/금고 출납 후 기입장과 잔액 대조.

수집 대상은 륜입니다. 사리·연등·재료 소비를 륜 지출로 환산하지 않습니다. 합계는 보관된 최근 기록 기준이며, 과거 누락 내역을 추정 복구하지 않습니다.

## 검증 한계

클라이언트 기입장·중첩 지출·합산/충돌·중복 표시·공동 지갑 처리 테스트와 SQL 삽입 위치 검사를 실행했습니다. PostgreSQL 실행 환경 및 운영 DB 접근이 없어 서버 SQL의 실제 실행/거래 통합 검증은 수행하지 못했습니다.
